Loop Engineering · 3 分鐘上手 回到對話 ↗ 完整說明

一個對話框，整台 Spark 都在後面

進站就是對話。要查資料、看模型、開 shell、寫需求、下任務——都從這裡出發，右邊一排圖示切面板，鍵盤 Alt+數字直達。

1問問題，答案附出處

回答完全在這台 Spark 上產生。勾著「引用知識庫」時，先檢索 CF-AOI 程式碼與文件，句尾標 [n] 出處。

做法：輸入問題 → Shift+Enter。可 Ctrl+V 貼截圖；答完可「重答」「存進知識庫」「轉成任務」「請雲端複核」。

2右側圖示列：七個面板

任務／調參／知識庫／PRD ─ 模型／機台／評比。點一下切換，再點同一個收起；圖示永遠在，面板不會「不見」。

快捷鍵：Alt+1～7；☰ 收左欄、▤ 收右欄，兩邊都收起時對話幾乎全螢幕。

3模型面板：下載 → 建置 → 切換

列出 spark-vllm-docker 裡每一個 recipe，每列只有一個下一步。三張推薦卡：對話、寫程式、小而快。

做法：Alt+5 → 按卡片上的按鈕。切換會重啟 vLLM（幾分鐘），先跳確認。「機台」（Alt+6）看記憶體、GPU、這次回答的速度。

4上網／工具：讓模型去查

模型自己不會上網；勾了晶片才把 web_search／fetch_url 交給它。搜尋走自架 SearXNG，不經第三方 API；內網一律擋。

做法：點「上網／工具」晶片再問。回答下方多一張工具卡（查了什麼、多久、來源網址）。

5MCP：讀 repo、查 PR

同一個晶片，多出 🧩 工具：唯讀檔案系統（只在登錄過的 repo 內）、Loop 自己的 API、GitHub（gh）。本地模型跑任務時也拿到同一組。

試試：「用工具列出 cf-aoi 的 ip/ 目錄並說明」「最近有哪些 PR？」路徑逃出 repo 會被拒絕。

6終端機：需要時再叫出來

底部抽屜裡是這台 Spark 的真 shell。收起不會關掉 shell，重開接回原畫面；只有白名單身分看得到。

做法：Ctrl+` 開關；＋ 開分頁、雙擊改名、拖上緣改高度。模型面板工作卡的「看 log」直接開 tail 分頁。

7PRD 精靈：五步變成任務

從「修改軟體」的角度引導：原始碼在哪、症狀→期望、用測試指令／圖集比對／人工清單驗證。本地模型幫找檔案、寫驗收條件；過閘門才建任務。

做法：Alt+4 → 「開新的 PRD」。圖集只以路徑引用，絕不複製。

8調參建議：只建議，人來套用

只引用知識庫裡真的存在的檔名與參數；不會改機台。建議可一鍵變成 Loop 任務，交給工程師驗證。

做法：Alt+2 → 填症狀 → 產生建議；或在對話勾「調參建議」晶片。

Demo 腳本（約 5 分鐘）

  1. 對話＋知識庫：問「RDMA 收圖為什麼會掉幀？」→ 看 [n] 出處與速度。

  3. 模型：Alt+5 三張推薦卡；指出 Coder Next 已「可切換」（映像剛從面板建好）。
  4. 上網：勾「上網／工具」，問「vLLM 最新正式版本？附來源」→ 工具卡 → 引用 GitHub。

  6. 終端機：Ctrl+`，nvidia-smi；收起再開，畫面還在。
  7. PRD → 任務：Alt+4 開精靈，走一遍五步（可用草稿），建任務 → 看板。
