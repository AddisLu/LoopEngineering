Loop Engineering · 3 分鐘上手 回到對話 ↗ 完整操作說明 連線前置作業

一個對話框，整台 Spark 都在後面

進站就是對話。查資料、看模型、開 shell、寫需求、下任務、比模型——都從這裡出發。每一頁都是同一套版面：左邊一排圖示換頁，右欄四個分頁用 Alt+數字直達。每張卡右下角有「完整說明」的對應章節。

從 issue 到 PR（3 分鐘）

修 bug 不用填表：給 repo 或 issue 網址、一段描述、截圖。Loop 先分析，你確認後它才修；檢查在設好的機台上跑，過了就開 Gitea PR、回 issue 留言。

  1. 1貼上來左邊「問題單」：貼 Gitea 的 issue 或 repo 網址，寫發生什麼事、期望怎樣，Ctrl+V 貼截圖 →「請 Loop 分析」。第一次用到的 repo 會先匯入（約 1 分鐘）。
  2. 2看分析卡30 秒到 2 分鐘：可能原因與位置、重現方式、驗收清單（這個 repo 的必過檢查＋重現紅→綠）、機台與模型。哪一塊不對就按「改一下」。
  3. 3開始修Loop 在隔離的 worktree 修，自己先跑到綠；引擎到機台跑全部檢查，修不好換下一個本地模型。主管模式按的是「送出核可」。
  4. 4看結果頁結論色塊、Loop 的自評、檢查清單、圖資逐案例、diff、嘗試記錄。按「合併」（走 Gitea PR，可以順便關 issue），或「退回修改…」寫一句話。
第一次之前：工程師先在 Repo 頁匯入 repo、設好它的「檢查」，在機台頁登記一台機台並按「檢查」。→ 完整說明第 5b 章

1問問題，答案附出處

回答完全在這台 Spark 上產生。勾著「引用知識庫」時，先檢索 CF-AOI 程式碼與文件，句尾標 [n] 出處。答到一半切到總覽再回來也不會斷——伺服器會繼續寫，回來自動接著播。

做法：輸入問題 → Shift+Enter。可 Ctrl+V 貼截圖；答完可「重答」「存檔」「存進知識庫」「轉成任務」「請雲端複核」。存檔會列出這則回答做得出來的東西：Markdown、HTML、PDF、簡報 .pptx，還有它畫的每張 SVG 與每段程式碼。→ 完整說明第 26 章

2左邊換頁，右欄四個分頁

每一頁都是同一套版面：左邊一排圖示換頁（對話・總覽・工作流程・評比・驗證方案・知識星圖・晨報），上方標題列有「你是 ○○」。對話頁的右欄只有四個分頁：需要你處理（和總覽同一套卡片）、調參、知識庫、模型（下半部是機台狀況）。點正在看的分頁會收起右欄。

快捷鍵：Alt+1～4 切右欄分頁；☰ 收對話紀錄、▤ 收右欄，兩邊都收起時對話幾乎全螢幕。→ 完整說明第 5 章

3模型分頁：下載 → 建置 → 切換

列出 spark-vllm-docker 裡每一個配方，每列只有一個下一步：下載、建置、或切換。跑不動的會寫原因（要兩台 Spark、權重沒下載完）。

做法：Alt+4 → 按卡片上的按鈕。切換會重啟 vLLM（幾分鐘），先跳確認；工作卡的「看 log」直接開終端機分頁。記憶體、GPU、速度在同一個分頁的下半部「機台狀況」。→ 完整說明第 26 章

4上網／工具：一個晶片，模型自己決定

模型自己不會上網。打開晶片就是把整組工具交給它，要不要用、用哪一個由它判斷，你不用挑。搜尋走自架 SearXNG，不經第三方 API；內網位址一律擋。

做法：點「上網／工具」晶片再問。回答下方多一張工具卡：查了什麼、花多久、來源網址。→ 完整說明第 26a 章

5MCP：讀 repo、查 PR

同一個晶片，多出 🧩 工具：唯讀檔案系統（只在登錄過的 repo 內）、Loop 自己的 API、GitHub（gh）。本地模型跑任務時拿到同一組。

試試：「用工具列出 cf-aoi 的 ip/ 目錄並說明」「最近有哪些 PR？」路徑逃出 repo 會被拒絕。→ 完整說明第 26a 章

6終端機：每個人自己的 worktree

底部抽屜裡是這台 Spark 的真 shell。第一次開會幫你切一份自己的 git worktree，主 checkout 不會被任何人的修改弄髒；下次再開還是同一份。收起不會關掉 shell。

做法：Ctrl+` 開關；＋ 開分頁、雙擊改名、拖上緣改高度。改完就 push 自己的 desk/… 分支。→ 完整說明第 26a 章

7工作流程：需求畫成一條流程

一件工作就是一條流程：需求 → 準備環境 → AI 實作 → 驗證 → 驗收門檻 → 人工核可 → 合併。缺什麼那個節點就亮 ⚠；按「檢查」本地模型先讀一次，過閘門才開始執行。草稿存在伺服器，開始頁的「最近的草稿」可以接著寫或刪掉。

做法：左邊「工作流程」或總覽的「＋ 新工作流程」。先挑一個驗證方案，驗證指令、門檻、人工清單一次帶好；圖集只以路徑引用，絕不複製。→ 完整說明第 5a 章

8調參建議與「轉成任務」

只引用知識庫裡真的存在的檔名與參數，不會改機台。任何一則回答按「轉成任務」都會先問你要哪一種：軟體修正與功能走工作流程、驗證新技術直接開一個新 repo 給它跑、待辦就只記一筆。

做法：Alt+2 填症狀產生建議，或在對話勾「調參建議」晶片。→ 完整說明第 26 章

9評比：同一題，幾個模型各做一次

題目可以是看板任務、工作流程草稿、自己出題，或內建題庫。每個模型各開一張任務去做，雲端評審看 diff 與驗證結果匿名打分，多位評審會標「一致」或「分歧」。新模型很多時先用快篩：勾幾個本地模型跑內建小題，不評分、不花額度，看誰值得進正式評比。

做法：左邊「評比」→「＋ 新評比」，或「快篩」分頁勾模型；在對話說「快篩 gpt-oss-120b」也行。花費只有評審那幾次雲端呼叫，送出前會先告訴你目前用量。→ 完整說明第 26 章

Demo 腳本（約 5 分鐘）

  1. 對話＋知識庫：問「RDMA 收圖為什麼會掉幀？」→ 看 [n] 出處與速度。
  2. 不怕切頁：答到一半點左邊「總覽」再回來，答案自己接上。
  3. 模型與機台：Alt+4 三張推薦卡，指出哪一個現在可以切換、哪一個還缺什麼；往下捲是記憶體、GPU、這次回答 tok/s。
  4. 上網：勾「上網／工具」，問「vLLM 最新正式版本？附來源」→ 工具卡 → 引用 GitHub。
  5. MCP：同一晶片，問「用工具列出 cf-aoi 的 ip/ 目錄並說明」→ 🧩 loop-fs 卡。
  6. 終端機：Ctrl+`，第一行就寫出你自己的 worktree；跑 nvidia-smi，收起再開畫面還在。
  7. 轉成任務：任一則回答按「轉成任務」→ 選「軟體修正」→ 工作流程草稿 → 檢查 → 開始執行 → 總覽排隊中。
  8. 評比：左邊「評比」看模型戰績；「快篩」分頁示範用小題先驗模型，「＋ 新評比」示範選題目、參賽模型與評審。
