SSoT 連接指南

讓你的任何應用程式（後端腳本、瀏覽器前端、或另一個 LLM/Agent）唯讀串接 Loop Engineering 的 SSoT——RAG 語料檢索、策展知識圖譜、擷取來源清單。三種連法都用同一把唯讀 token，只能查、不能改。

唯讀 · 寫入一律 403 REST / 瀏覽器 / MCP 三種消費者 Tailscale tailnet only

01總覽：唯讀邊界

Loop Engineering 的看板/API 原本只有一把全權 token（LOOP_API_TOKEN）。第二把唯讀 token（LOOP_READONLY_TOKEN）是專門給「其他應用來查 SSoT」用的：範圍被硬限制在下面這幾個 GET 路徑（伺服器端白名單，見 src/server/app.ts 的 READONLY_PREFIXES）：

路徑前綴用途
GET /api/rag/search混合 RAG 語料檢索（FTS ⊕ 向量 KNN）
GET /api/knowledge...策展知識（含 /api/knowledge/graph）
GET /api/sources已登錄的擷取來源清單
GET /api/status排程/用量狀態（輕量健康檢查）
🔒只能查、不能改。用唯讀 token 打非 GET 方法（POST/PUT/DELETE）或白名單以外的路徑（例如 /api/tasks），一律回 403；帶錯 token 或完全不帶則回 401。

三種消費者、同一把 token：

  1. REST——任何後端服務或腳本，直接帶 Authorization: Bearer 打 API（第 2 章）。
  2. 瀏覽器前端——需伺服器另外開 CORS 白名單（第 3 章）。
  3. 其他 LLM/Agent——透過唯讀 MCP server，經 tailscale serve 對外暴露（第 4 章）。

02REST（後端/腳本）

Base URL 依你打哪裡而定：

  • 經 tailscale serve 對外：https://<host>.<tailnet>.ts.net
  • 本機同一台機器：http://127.0.0.1:4711

每個請求都帶 Authorization: Bearer $LOOP_READONLY_TOKEN。

混合 RAG 檢索

curl -sS "$LOOP_API_URL/api/rag/search?q=%E6%9F%A5%E8%A9%A2" \
  -H "Authorization: Bearer $LOOP_READONLY_TOKEN"

選填 query 參數：scope（限定某個已登錄來源的 uri 前綴）、kind（限定文件類型，如 md/ts）、topK（回傳筆數上限）。

策展知識搜尋

curl -sS "$LOOP_API_URL/api/knowledge?q=OpenProject" \
  -H "Authorization: Bearer $LOOP_READONLY_TOKEN"

知識圖譜

curl -sS "$LOOP_API_URL/api/knowledge/graph" \
  -H "Authorization: Bearer $LOOP_READONLY_TOKEN"

擷取來源清單

curl -sS "$LOOP_API_URL/api/sources" \
  -H "Authorization: Bearer $LOOP_READONLY_TOKEN"
ℹ️唯讀 token 只能打這四類 GET；其餘一律 403（見第 1 章白名單）。

03瀏覽器前端

瀏覽器直接 fetch 是跨網域請求，預設會被瀏覽器擋下——伺服器端要先把前端的 origin 加進 LOOP_CORS_ORIGINS（逗號分隔，多個 origin 可並列），再重啟服務：

# ~/.config/loop-engineering/env
LOOP_CORS_ORIGINS=https://my-frontend.example.com,http://localhost:5173

前端呼叫範例：

const res = await fetch('https://<host>.<tailnet>.ts.net/api/rag/search?q=hello', {
  headers: { Authorization: 'Bearer ' + READONLY_TOKEN },
});
const { results } = await res.json();
⚠️瀏覽器只放唯讀 token。前端程式碼（含打包後的 JS）任何人都能看到，絕對不要把全權 LOOP_API_TOKEN 放進瀏覽器——唯讀 token 就算外洩，最壞情況也只是被查詢，不能寫入或執行任務。

CORS 只允許 GET／OPTIONS 與 authorization／content-type header；沒設 LOOP_CORS_ORIGINS（預設空）＝完全不註冊 CORS，行為與原本一致。

04其他 LLM/Agent（MCP over network）

另一顆機器上的 Claude Code（或任何支援 MCP 的 agent）可以透過唯讀 MCP server（Streamable HTTP）直接查 SSoT，不需要自己組 REST 請求。伺服器監聽 LOOP_MCP_PORT（預設 4713，僅綁 127.0.0.1），跟看板一樣經 tailscale serve 對外。

claude mcp add --transport http loop-ssot \
  https://<host>.<tailnet>.ts.net:4713/mcp \
  --header "Authorization: Bearer $LOOP_READONLY_TOKEN"

實際 tailscale serve 路徑/port 對應以你的部署設定為準；也可用環境變數方式帶 token（依你的 MCP client 支援程度）。

工具（僅唯讀三個）

工具作用
loop_search混合 RAG 檢索語料庫，回帶引用的片段（路徑/行號/分數）
loop_recall全文搜尋策展知識庫（環境／偏好／限制／事實）
loop_sources列出已登錄的擷取來源

資源

URI內容
ssot://sources已登錄擷取來源（同 loop_sources）
ssot://graph策展知識圖譜（nodes/edges）
✅這個 MCP server 完全不含任務／部署／排程的變更工具——就算 client 端被誤導去呼叫「新增任務」之類的動作，伺服器上根本沒有這個工具存在。檔案：mcp/loop-ssot-mcp.mjs。

05唯讀 token 取得

唯讀 token 存在 ~/.config/loop-engineering/env 的 LOOP_READONLY_TOKEN，跟全權 token 一樣不會印在這份文件裡。在主機上取值：

grep '^LOOP_READONLY_TOKEN=' ~/.config/loop-engineering/env | cut -d= -f2
🛡️Token 治理慣例：絕不寫死在程式碼、絕不複製到別的檔案——每個消費者（REST 腳本／前端／MCP client）都應該在啟動時從環境變數或這個 env 檔即時讀取。

06極簡 Client（clients/）

不想自己組 HTTP 請求，repo 裡已附兩支可直接照抄的極簡唯讀 client——都是零額外依賴（Python 只用 stdlib、Node 只用內建 fetch），設定解析邏輯一致：先看環境變數，沒有就退回 ~/.config/loop-engineering/env，都沒設 token 就直接報錯、非零結束，不會靜默用空 token 打出去。

Python（clients/ssot_client.py）

export LOOP_READONLY_TOKEN=...   # 或放進 env 檔
python3 clients/ssot_client.py search "查詢字串"
python3 clients/ssot_client.py recall "查詢字串"
python3 clients/ssot_client.py sources
python3 clients/ssot_client.py graph

當函式庫用：from ssot_client import SsotClient; SsotClient().search("q")。

Node（clients/ssot_client.mjs）

export LOOP_READONLY_TOKEN=...   # 或放進 env 檔
node clients/ssot_client.mjs search "查詢字串"
node clients/ssot_client.mjs recall "查詢字串"
node clients/ssot_client.mjs sources
node clients/ssot_client.mjs graph

當模組用：import { SsotClient } from './clients/ssot_client.mjs'; await new SsotClient().search('q');

📄兩支 client 都對應第 2 章的四個唯讀端點：search → /api/rag/search、recall → /api/knowledge、sources → /api/sources、graph → /api/knowledge/graph；CLI 模式印出的是伺服器回應的原始 JSON。
