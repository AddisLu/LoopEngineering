Loop Engineering 完整操作說明

一套用量感知（token-aware）的自主編碼任務排程器 ＋ 協作器。它把編碼任務排入佇列、以必填欄位審核把關，並在你的 Claude 用量低於日/夜門檻時，逐一派給無頭的 Claude Code 在隔離的 git worktree 中執行，跑完你的驗證步驟後停進「待結案」欄，等你收尾。設計為 24/7 常駐 Linux 主機、透過 Tailscale 遠端監看／暫停。

MAX 訂閱 · 以用量百分比排程 單一 Node 程序 ＋ SQLite 看板 · SSE 即時更新 M1–M4 完成

01這是什麼

Loop Engineering 解決一個問題：你想讓 Claude Code 自動、連續地完成一批編碼任務，但又不能燒爆你的訂閱用量。它是一個常駐的「調度大腦」，核心行為是：

  • 排入佇列：把每個編碼任務（目標、計畫、驗證步驟、repo）建成一張卡片。
  • 把關（gate）：必填欄位不齊，任務無法進入排程。
  • 用量感知調度：每 60 秒一個 tick，只有在 session／weekly 用量百分比低於當前時段門檻、且有足夠 runway 時，才派工。
  • 隔離執行：在專屬 git worktree 中跑 Claude Code（無頭、串流 JSON），自動 commit，再跑你的驗證指令。
  • 停進待結案：驗證通過 → review 欄等你人工收尾；失敗 → failed。
ℹ️為什麼用「百分比」而非「金額」？本工具是為固定的 MAX 方案設計，排程依據是用量百分比（session 5 小時窗、weekly 窗），而非美金花費——訂閱制下額度才是限制。

架構一句話

單一 Node 程序 ＋ SQLite（WAL 模式）。沒有 Redis／訊息佇列——用行程內的 60 秒 tick 搭配 mutex 與 max_concurrency。用量透過 TokenBar 的 oauth/usage 契約讀取（session／weekly %），並有 ledger 後備。

02任務生命週期

每張任務卡片會沿著這條狀態機前進：

draft→（審核）→ queued→ running→ verifying→ review→ closed
running 遇到 ⤵ failed（timeout／驗證失敗） blocked（斷路器／使用者暫停 → 可自動 resume 回 running）
狀態意義看板欄位
draft剛建立，尚未通過入場審核Draft · 入場審核
ready審核通過、尚未加入排程Ready
queued已入列，等待調度派工Queued
runningClaude Code 正在 worktree 中執行Running
verifying正在跑你的驗證步驟Verifying
blocked被斷路器或使用者中斷，保留 session 以便自動續跑Queued（可自動 resume）
review驗證通過，待你人工結案Review · 結案
failed逾時或驗證/執行失敗Review · 結案
closed你已結案，流程結束Closed

04遠端存取（MacBook Air / 手機）

看板只走你的私人 Tailscale 網路（tailnet），不對公網開放。由於已啟用 token，第一次開啟必須帶 token，之後瀏覽器會記住。

步驟 1 — 取得帶 token 的完整網址

在主機終端機執行（基於安全，token 不寫在本手冊內；此指令會印出可直接開的完整網址）：

echo "https://addis-b850m-ds3h.tailffdb68.ts.net/?token=$(grep '^LOOP_API_TOKEN=' ~/.config/loop-engineering/env | cut -d= -f2)"

步驟 2 — MacBook Air（已在 tailnet，免安裝）

  • 把上一步印出的網址貼進 Safari / Chrome → 看板出現。
  • token 會存進 localStorage，之後直接開 https://addis-b850m-ds3h.tailffdb68.ts.net/ 即可（免 token）。可加入 Dock。

步驟 3 — 手機

  1. 安裝 Tailscale App（App Store / Play 商店）。
  2. 登入同一帳號 addislyu@，打開開關。
  3. 瀏覽器開同一串帶 token 的網址 → 可「加入主畫面」變 App 圖示。
⚠️只能用 HTTPS + MagicDNS 主機名這個網址。憑證綁定 addis-b850m-ds3h.tailffdb68.ts.net；http://100.65.248.121:4711 這類 IP 網址不通（服務只綁 127.0.0.1、對外一律經 tailscale serve）。
🔓想免 token？私人 tailnet 本身就是邊界。要拿掉第二層驗證：
sed -i 's/^LOOP_API_TOKEN=/#LOOP_API_TOKEN=/' ~/.config/loop-engineering/env
systemctl --user restart loop-engineering
之後所有裝置直接開網址即可。代價：tailnet 內任何裝置皆可存取、無驗證。

06新增任務與入場審核

點頂欄「＋ 新增 task」填寫欄位。入場審核（gate）會逐項檢查；未通過的任務無法加入排程，卡片上會標紅缺項。

欄位必填說明 / 審核規則
Title是任務標題。
Goal是目標描述，不可空白。
Plan是計畫參照：存在的 .md/.html 檔路徑，或合法 URL。
Tool是claude-code 或 mock（mock 為零 token 測試用）。
Verify steps是至少一條驗證指令（逗號分隔），例：npm run lint, npm test。
Repo path是*存在的 git repo 目錄。mock 略過
Base branch是*存在的基底分支。mock 略過
Complexity—S/M/L（預設 M）；決定逾時、預估用量與模型路由。
Priority—整數，預設 2。
Setup cmd—派工前在 worktree 執行的準備指令（如 npm ci）。未填只是警告。
Model—sonnet/opus/default（不填則依複雜度路由）。

* Repo/branch 僅在工具為 claude-code 時必填；mock 在暫存目錄執行，故略過 repo 檢查。

07CLI 指令參考

在主機 repo 目錄執行。兩種呼叫方式：開發用 npm run loop -- <cmd>，或用建置產物 node dist/cli.js <cmd>。

指令作用
add建立任務（起始 draft）。旗標：--title* --goal* --plan --tool --verify --setup --repo --base --complexity --priority --model
gate <id>顯示該任務的入場檢查清單。
queue <id>審核並把 draft 加入排程。
list [--status <s>]列出任務（可依狀態過濾）與各狀態計數。
status顯示排程暫停狀態、session/weekly 用量、各狀態計數、進行中的 run。
pause [--hard]暫停排程。--hard 會一併中斷執行中的 run（轉 blocked，可 resume）。
resume恢復排程。
abort <id>中斷該任務的 run 並標記 failed。
close <id>把已審閱的任務標記 closed。
set-usage --session <%> [--weekly <%>]開發用：強制寫入共享用量快取（斷路器演練）。

範例

cd ~/Coding/LoopEngineering

# 建立任務
npm run loop -- add --title "修 auth bug" --goal "修正登入逾時" \
  --plan ./plan.md --repo /path/to/repo --base main \
  --verify "npm test" --complexity M

npm run loop -- gate <id>      # 看審核清單
npm run loop -- queue <id>     # 審核 + 入列
npm run loop -- status         # 排程與用量總覽
npm run loop -- list --status review

09三層預算保護

為避免燒爆用量，派工到執行有三道獨立防線：

① 派工前 gate

tick 時先看用量快照：若 session/weekly 已達當前時段門檻，或 runway 不足 min_runway_min，就不派工。

② 執行中斷路器

執行期間若用量衝破 hard_limit_pct（95%），立即中斷該 run（SIGINT → SIGKILL），任務轉 blocked（保留 session，用量降回後自動 resume）。

③ 每run watchdog

每個 run 有依複雜度而定的逾時（S/M/L = 15/45/120 分）；逾時即殺並標 failed。

🛡️另有內層保險：PreToolUse 的 budget-guard.mjs hook 會在硬上限阻止工具使用——即使排程層失守，被派出的 Claude 也會被擋下。

12MCP：在編輯器一句話派工

Loop Engineering 已包成一個 MCP server（loop-engineering），註冊在 Claude Code。你在 VS Code 的 Claude Code 對話裡，只要描述「要修什麼」＋「目標」，其餘欄位自動偵測、自動建立任務並排程——不必開看板、不必手打 CLI。

✅最小輸入。你只需要給「目標」。repo、base 分支、驗證步驟、setup 指令、計畫檔全部自動偵測；偵測不到的才回頭問你。

怎麼用

在任一 repo 的 Claude Code 對話裡直接說，例如：

把登入逾時的 bug 交給 Loop Engineering：目標是修正 session 過期判斷。

Claude Code 會呼叫 loop_add_task，自動填好並預設直接排程。想先在看板確認就加一句「先建 draft」（→ queue=false）。

自動偵測了什麼

欄位自動來源
repo_path目前工作區 / git 根目錄（Claude Code 明確帶入最準）
base_branchorigin 預設分支 → 否則 main/master
verification_stepspackage.json scripts（如 npm run typecheck, npm test）／go／cargo／python／Makefile
setup_cmdnpm ci／pnpm／yarn／pip（依 lockfile）
plan由 title＋目標＋驗證步驟自動合成為 .md 存檔
title由目標推導（可自訂）
⚙️預設直接排程（queue=true）。描述完即入列，額度允許時自動執行。要保留為 draft，說「先建 draft」；想 zero-token 試流程可要求用 mock 工具。

loop_list_tasks看板摘要（可依狀態過濾）

設定與維護

  • MCP 打本機 http://127.0.0.1:4711，token 自動從 ~/.config/loop-engineering/env 讀取——不用手動帶。
  • 新增/更新 MCP 後需重開一個 Claude Code 對話（或重載視窗）才會載入工具；用 /mcp 確認 loop-engineering 為 Connected。
  • 檔案：mcp/loop-mcp.mjs。註冊：claude mcp add --scope user loop-engineering -- node ~/Coding/LoopEngineering/mcp/loop-mcp.mjs
⚠️因預設直接排程執行，請確認目標 repo 與驗證步驟正確——執行會實際動用 Claude Code 額度。每次的自動偵測結果都會回報，過目再放行。
